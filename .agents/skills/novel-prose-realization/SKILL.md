# Mission

本 Skill 是 Story MVP 的 Novel Prose Realization / Humanizer-zh 执行层。

它只回答：

> 已经决定的本章事件，怎样落成自然、具体、连续、有角色感的中文商业长篇小说正文？

它不回答“下一章发生什么”，不负责创意、总纲、十章规划、成长循环、GBrain 检索、故事事实审批或章节保存。

本 Skill 吸收 Humanizer-zh 中可迁移的原则，并结合《第一序列》《将夜》《诡秘之主》的书写方式蒸馏进行修订。
这些来源只用于形成抽象控制；禁止复制原文、模仿作者声音、迁移角色口癖或使用签名句法。

# Current MVP Mapping

当前 cleanroom MVP 不建立第二套 Canon、Chapter Contract、RevisionUnit、Prose DNA 数据库、Humanizer Agent、
风格评分器或独立 `/api/humanize`。

当前实际输入已经足够：

- 已保存的前文正文；
- BOOK 中的当前状态和未兑现承诺；
- 当前大型剧情块；
- 当前十章计划；
- 当前章具体小纲；
- 最近章节摘要；
- BOOK 的 `## 7. 叙事结构`；
- BOOK 的 `## 8. 文风与可操作参数`；
- BOOK 的 `## 9. 对话特点`；
- BOOK 的 `## 10. 节奏结构`；
- 作者在当前任务中明确给出的表达意图；
- 当前章节期 `WORLD AUTHORITY` 的安全世界事实投影；
- Outline 为当前章排程的 `Reader Release`（若有）。

BOOK §7—§10 共同构成当前书的 `Current Book Prose Profile`。完整 World Vision 不是 Writer 的自由检索库：Writer 只使用 runtime / Curator 已投影到当前章的安全世界事实。

# Authority

## 已发生事实

下列内容是已经发生的事实，Prose Realization 不得修改：

1. 已保存的前文正文；
2. BOOK 当前状态中已经确认的事实；
3. 已建立的人物位置、身体状态、知识、关系、资源、能力、物品和未完成即时目标。

## 本章必须发生

当前章具体小纲决定本章必须完成的：

- 触发事件；
- 推动事件的人；
- 主角行动；
- 对手或世界反应；
- 直接结果；
- 状态变化；
- 叙事功能；
- 结尾推动力。

小纲不能覆盖已经发生的事实。二者冲突时，保留前文事实并显式报告冲突，不用 prose 偷偷修故事。

## 方向约束

当前大型剧情块、当前十章计划和 BOOK 总体设计提供方向，但不能替代当前章小纲，也不能授权 Writer 提前兑现未来事件。

## 世界事实与首次释放

`WORLD AUTHORITY` 决定章节期可用的安全世界事实；`Reader Release` 决定当前章是否到了第一次告诉读者的时机。Writer 不从完整 World 自选说明主题，也不因为“读者可能不知道”而补造世界史。

- 动作先制造自然问题；
- Reader Release 已给出事实时，用最短充分的直接旁白回答“它是什么 / 为什么此刻重要”；
- named 势力 / 地点 / 身份的安全公开类别已排程时，第一次需要识别可直接说清一次，不要求读者靠外观猜；
- 如果某答案在未来计划中仍是 discovery / reveal，揭晓前继续未知；
- 说明完成立刻回到行动，不把 Orientation 追加成百科段。

## 表达优先级

只在“怎么写”层面使用：

`Current Book Prose Profile`
→ `Author Explicit Prose Intent`
→ `Selected Abstract Scene Profile`
→ `Generic Prose Realization Guidance`
→ `Generic LLM Prior`

GBrain Story Inspiration 和 Reference Programs 默认只影响故事结构、压力、成长和事件选择，不自动成为文风来源。

# Before Writing

开始 Writer A 之前，先在内部确认以下连续性事实；不要把内部检查过程当作正文输出：

- 当前章节编号；
- 上一章结束的时间和地点；
- 在场人物；
- 每个人当前身体状态和情绪；
- 主角手中实际存在的物品、资源和能力；
- 最后动作、最后一句对话和未完成即时目标；
- 当前人物知道什么、不知道什么；
- 当前小纲要求的八个字段；
- 本章结束时必须成立的新状态；
- BOOK §7—§10 的本书表达控制。

任何物品、能力、关系、线索或知识如果没有前文、小纲或 BOOK 支持，不得因为写起来方便而加入。

# Abstract Scene Profiles

每章可以选择一个主 profile，也可以有界组合两个。它们是抽象工具，不对应任何来源作者。

## Practical-Comic

适合生存、资源、交易、团队磨合和快速兑现。

- 让人物通过用途、成本、风险和现实反应理解世界；
- 行动链直接；
- 对话口语化，允许讨价还价、避答和轻微反转；
- 回报尽快变成可见结果；
- 幽默来自处境与人物反应的落差。

限制：不要让所有人共享同一种笑点节奏，不要每次 payoff 都用围观震惊，不要在场景后补主题口号。

## Lyrical-Subtext

适合关系余波、历史重量、宏观空间、大场景蓄势和安静收束。

- 允许叙述距离有目的地拉远再收近；
- 只选一两个能够反复承载意义的物件或景象；
- 让沉默、姿态、食物、天气和空间关系承载情绪；
- 关键动作落笔可以比铺垫更朴素；
- 章末可以留下余韵而非硬悬念。

限制：不要让每个场景都抒情，不要给每个动作配比喻，不要让作者声音吞掉人物声音。

## Analytic-Mystery

适合调查、规则发现、仪式、专业操作和战术博弈。

- 按 POV 可观察顺序给信息；
- 观察可以产生假设，但假设必须影响下一步；
- 通过试探、验证、排除或行动更新判断；
- 使用少量精确、可验证的物件和环境细节；
- 不确定性应逐步降低，而不是只堆问题。

限制：不要分析每一个细节，不要让所有角色都像同一个理性分析器，不要把场景写成会议纪要或实验报告。

# Shared Draft Protocol

Normal Draft 和对已有草稿的 Revision Draft 共用同一协议。

## Writer A — Scene Draft

Writer A 负责把当前章小纲完整写成实际发生的场景。

优先完成：

- 场景入口；
- 人物行动；
- 对话；
- 环境参与；
- 对手或世界反应；
- payoff；
- 直接结果；
- 状态变化；
- 章末推动。

Writer A 不追求先“写得漂亮”。先保证事情真的发生，而不是把小纲换成更长的概述。

## Writer B — Continuity & Realization

Writer B 必须完整阅读 Writer A 和前文上下文，重点修复：

- 场景瞬移；
- 时间或地点断裂；
- 人物、物品、能力或知识突然出现；
- 上一章钩子没有承接；
- 因果桥缺失；
- 重要动作被一句概括；
- 对手反应或空间变化缺失；
- 关系反应不连续；
- scene realization 太薄。

Writer B 可以增加不改变事实的桥接动作、现场反应和 realization-only micro-event，但不得改变小纲的主要事件、
直接结果、状态变化、payoff 或结尾推动。

## Writer C — Prose Realization & Bounded Humanization

Writer C 必须完整阅读 Writer B，再完成最终正式正文。

重点修复：

- 重复能力解释；
- 重复身体状态；
- 同一情绪由动作、内心、旁白和总结连续复述；
- 均匀句长和均匀段长；
- 每段都用金句、总结或悬念收尾；
- 对话只用于讲资料；
- 泛化环境描写；
- 机械连接词串联；
- 机械三段式和重复否定排比；
- payoff 的“预告一次—发生一次—总结一次”；
- 无新信息的普通路程和重复动作；
- 模板化的章末钩子。

Writer C 可以重组句子和段落，但不得改变 Writer B 已经确定的事实、事件顺序、人物意图、线索、资源、
能力、payoff、不可逆改变、直接结果、状态变化和章节结尾。

# Cross-Book Prose Controls

以下是三部来源共同支持、可跨书迁移的软控制。

## 1. 先让当前行动成立

场景开始后应尽快让读者知道：谁正在做什么、为什么此刻必须做、现场有什么限制。

宏观或氛围开场可以存在，但必须与当前行动形成收束关系。

## 2. 说明绑定需要

世界、制度、能力和历史信息应绑定人物当前的选择、风险、关系或任务。

直接说明不是错误；**高价值 Reader Orientation 不是水文**。当当前动作第一次让读者自然追问“这是什么 / 为什么重要”，且 Curator 已提供安全事实时，可以用 1—3 个短旁白段回答到够用，然后立即回到现场。

不要用“多轮人物确认 / 重复验证 / 普通实施”来替代本来一小段世界坐标就能提供的信息；也不要把未排程的 World 事实自行补进正文。

## 3. 具体先于抽象结论

优先用动作、物件、停顿、距离、环境变化和实际结果承载信息。

读者已经能看懂时，不立即追加同义旁白总结。

## 4. 叙述距离有目的地变化

近距离用于感知、偏见、推理、犹豫和即时选择；较远距离用于空间、群体变化、制度或时间跨度。

距离变化必须有功能，不在同一关键动作后同时叠加事件说明、角色思考、旁白解释和主题总结。

## 5. 节奏服从压力

不存在统一正确的句长、段长或标点率。

危险和决断可以更短；观察、关系、说明和余波可以更长。Humanizer 检查的是模式失去功能后的机械重复。

## 6. 对话必须改变现场

每轮对话至少推动一种变化：信息、关系、选择、风险、行动、身份判断或情绪距离。

允许避答、误解、抢话、停顿、未完成的话和用动作回答。

## 7. 内心必须影响下一步

内心可以计算、误判、自我修正、掩饰、犹豫或暴露情感，但不能只是给读者重复已经看见的事情。

## 8. 已成立的 Supporting Skill 只保留结果级因果

如果某项手艺、诊断、制作、维修、路线、车具、医学、调查等方法已经在前文成立，而且它不是当前 Core Fantasy：

- 后续复用默认写“主角做了什么 → 为什么这一下有效 → 局势怎样改变”；
- 不重新把方法展开成步骤、微调、验证流程或小型解题场；
- 只有本章出现新边界、失败、反制、质变，或该专业本身就是作者明确选择的第二幻想轴时，才重新展开方法。

如果 Curated Context 已经把普通实施压成结果，Writer 不应为了让场景“完整”把步骤补回来。

## 9. 动作保持因果和空间

优先写清：

`看见什么 → 做什么 → 对方怎样反应 → 空间或条件怎样改变 → 下一步被限制或打开`

不要把战斗写成技能名列表，也不要在每招后补同义胜负判断。

## 10. Payoff 只解释一次

回报应在场景中实际完成。可以有必要余波，但不要同时提前宣布、现场展示、事后再总结同一层意义。

## 11. 情绪允许延迟和不完整

人物可以先处理任务，再在安全处、关系动作、物件或沉默中显露情绪。

不要强迫每次情绪都立即命名、解释和升华。

## 12. 章末携带状态变化

章末可以是动作、对话、信息重解、身份变化、关系停顿、安静威胁或新问题。

不要求每章 cliffhanger，但读者应能感到本章之后有什么已经不同。

## 13. Humanizer 审查结构，不审查词表

短句、省略号、问号、叹号、解释、作者旁白、排比或某个连接词都不是全局禁用项。

只有当它们在当前文本中重复到失去场景功能时，才进入修复。

# Diction Controls

这些是 prose soft controls，用来帮助 Writer 选择更准确的词，不是 schema、validator、Hard Gate、禁词表或风格评分器。最终服从当前 BOOK §7—§10、人物、POV 和场景压力。

## 名词：优先具体载体

优先使用当前 POV 人物能够看见、触摸、使用、搬动、失去、交换或绕开的具体名词。抽象概念可以使用，但如果能通过物件、身体状态、空间、制度后果或人物选择落地，就优先落地。

不要为了“具体”机械增加没有功能的细节。一个具体名词应当帮助读者理解当前判断、限制、关系、风险或行动。

## 动词：优先方向、接触与结果

动作尽量回答：

`从哪里 → 朝哪里 → 接触什么 → 什么发生改变 → 下一步因此怎样`

优先写出真正发生的移动、抓取、推开、压住、避让、拆解、交换、阻断和转向等现场行为，而不是大量用抽象动词代替场景。

“进行”“产生”“形成”“实现”等词不是禁词；只有它们替代了本可写清的实际动作时，才在 bounded repair 中修复。不要建立动词黑名单。

## 修饰词

形容词和副词优先保留真正会改变当前 POV 判断的性质：太滑所以无法站稳，太窄所以只能侧身，太烫所以不能直接抓，声音太轻所以只有近处人物听见。

不要堆多个近义修饰词来制造“文学感”。这不是“一句话只能有一个形容词”的规则。

## 不确定词

“似乎”“仿佛”“可能”“大概”“应该”“显然”“突然”“竟然”都不是禁词。只有在 POV 确实无法确认、判断暂定、后续信息可能修正，或变化真正超出人物预期时使用。

不要让模型习惯性给每个观察加一层“似乎”。

## 语体

词汇服从人物身份、人物关系、当前压力和当前场景。不要全局口语化、全局书面化，也不要为了“高级感”强行古雅。

专业现场允许专业词，但专业词第一次真正进入故事时，至少应改变选择、风险、行动、理解、机会或关系中的一项。

## 重复

区分有功能的重复与无功能的重复。

有功能的重复包括压力累积、仪式、关系回声、情绪回响和 payoff 回扣。无功能的重复包括相同修辞模板、相同句首、相同“不是 X 而是 Y”、相同“第一、第二、第三”、相同情绪解释和相同能力说明。

Humanizer 只主动修第二种，不把一次合理重复误判为问题。

# Sentence Architecture

以下是 Writer 根据场景选择的句法关系，不是固定模板。每段不必套用，也不要求覆盖全部关系。

## 基础行动

`锚点 → 动作 → 反应 → 条件改变`

适合普通动作和空间连续性。条件改变应当限制或打开下一步，而不只是作为动作后的同义总结。

## POV 推断

`观察 → 暂定解释 → 新细节 → 修正判断 → 行动`

适合调查、战术、规则发现和专业现场。推理最后必须影响行动，不能停在分析。

## 物象反思

`具体物象 → 关系 / 记忆 → 判断 → 简短落点`

适合 aftermath、关系、情绪和较慢场景。不要自动把每个物件写成象征。

## 对话

`一句话 → 微动作 / 停顿 → 对方行动 / 拒绝 / 改变`

对话的结果应进入现场。不要立刻追加“这句话体现了他的……”式旁白解释。

## 说明

`当前需要 → 最少必要事实 → 选择 / 风险变化 → 回到动作`

避免百科式连续说明。说明结束后应改变人物能做、知道、判断或承担的事情。

## 情绪

`动作 / 物件 → 未完全说出的感受 → 选择 / 沉默`

不要求所有情绪都显式命名。沉默、回避和不完整可以是有效结果。

## Payoff

`执行 → 可见结果 → 外界反应 → 一次确认 → 新行动空间 / 新压力`

不要使用“提前宣布 → 实际发生 → 再总结同一意义”的三重说明。

# 句长与段落

- 长句适合承载空间、关系、因果、观察和犹豫；
- 中等长度句承担主要推进；
- 短句用于决断、转折、危险落点、笑点和安静余波；
- 高压场景可以收紧句段；
- 普通、关系、exposition 和 aftermath 场景可以拉长；
- “多写短句”不是 Humanizer 目标；
- 不要让整章保持完全相同的句段长度。

这些选择服务于场景功能，不形成句长阈值或段落 validator。

# Scene Guidance

## Opening

开篇可以是人物直接入场、强冲突、宏观视角、神秘事件、日常反差或其他 BOOK 已选策略。

无论形式如何，开篇必须最终落到当前人物、当前问题和当前限制，不能只留下题材宣传片。

## Ordinary Scene

日常场景必须至少改变一项可感知状态：关系、资源、信息、计划、身份判断、能力理解或下一步行动。

“平静”不等于无状态变化。

## Dialogue Scene

先明确参与者各自想得到、隐瞒或避免什么。不要让人物轮流朗读设定。

角色声音来自词汇、句长、礼貌、攻击性、避答方式和沉默方式，不来自固定口癖清单。

## Action Scene

动作前建立位置、目标和限制。关键节点写清反应和空间变化。感官细节只选择能改变判断或行动的部分。

## Exposition Scene

可以系统说明，但必须有明确容器和动机，例如调查、教学、记录、争论、任务准备、交易或验证。

说明结束后应改变人物能做、知道、判断或承担的事情。

## Payoff Scene

让能力、资源、身份、关系或秘密在现场产生实际结果。外界反应可以强化兑现，但不能替代实际结果。

## Aftermath

余波用于更新代价、关系、认知、下一步和未解决感受。不要把已经清楚的胜负完整复述一遍。

## Emotion Scene

选择少数真实承载物：动作、身体、物件、距离、注意力或沉默。不要把每种渠道同时用满。

## Ending

章末选择与本章状态变化相匹配的落点。避免每章都使用同一种“突然有人出现”或“一句话揭示更大秘密”。

# Anti-AI Prose Audit

对每个 Draft 只做结构性、可解释的审阅，不计算 AI 分数。

检查：

1. 本章是否真的发生，还是只把小纲扩写成概述；
2. 上一章最后状态是否被直接承接或自然桥接；
3. 人物、物品、能力、知识和地点是否都有来源；
4. 重要动作、反应和后果是否先于抽象结论；
5. 同一事实或情绪是否被重复解释；
6. payoff 是否被三重说明；
7. 对话是否改变现场，角色声音是否可区分；
8. 高低压力场景是否有节奏变化；
9. 说明是否绑定当前需要；
10. 内心是否影响下一步；
11. 章末是否保留小纲要求的结尾状态；
12. 是否出现来源句法、来源口癖、专名或作者模仿。

这些是 review triggers，不是逐词禁用清单。

Audit 只报告真实存在且能定位的问题。正文正确时明确说正确，不制造 finding。

# Bounded Repair

Repair 只处理：

- scene realization 过薄；
- 缺失的短因果桥；
- 重复解释；
- 泛化措辞；
- 不自然对话；
- 均匀节奏；
- 机械连接；
- 无必要总结；
- 感官和动作缺少必要落点；
- 章末模板重复。

Repair 不得改变：

- 已发生事实；
- 当前小纲的主要事件；
- 人物意图；
- 知识边界；
- 关键线索；
- 资源或能力状态；
- payoff；
- 直接结果；
- 状态变化；
- 不可逆改变；
- 结尾推动。

如果只有修改故事决定才能解决问题，保留故事决定并报告冲突。

# Source-Style Leakage Boundary

禁止：

- 复制来源正文或长摘录；
- 指令化地“模仿某位作者”；
- 把一本来源书当成唯一 exemplar；
- 迁移来源角色口癖、专名、签名隐喻或长句法；
- 将 Story Reference Program 当作文风卡；
- 把来源书名、作者名、原文片段或来源定位注入运行时章节 Prompt；
- 用来源观察覆盖当前 BOOK 的明确表达控制。

来源蒸馏只允许产生抽象变量、场景 profile、失败风险和软控制。

# Output Boundary

输出格式服从调用方已经定义的 chapter response contract，不另造第二套 wrapper。

必须保证：

- `chapter-NNNN.md` 只保存 Writer C 的正式小说正文；
- Audit、字符数、事实摘要、SUBAGENT_MODE 和 provenance 与正文分离；
- 不输出 Writer A/B/C 的内部推理过程；
- 不把 Audit 或事实摘要混进小说正文；
- 不自动写入 BOOK；
- 不自动批准或覆盖已有章节。

如果调用方只要求正文，只返回正式正文。如果调用方要求正文与审阅分区，严格使用调用方给出的标记。
