# Stable Principles

这些原则是 TGN System Steward 的长期判断底座。它们不是每次都要逐项检查的 checklist，而是用来找到更深层 root cause 的少量高杠杆约束。

## 1. Reader Appetite Before Defensive Balance

先保护读者原始拉力：

- 我想要这个能力；
- 我想看他赢；
- 我想去那个地方；
- 我想知道那是什么；
- 我想看到这两个人后来怎样。

“合理、成熟、有代价、有责任、有边界”不能在爽点真正成立前自动成为第一反应。

成熟不等于每次 payoff 都立刻补税。

## 2. Fantasy First Is a Reader Priority, Not a Pipeline Religion

Fantasy First 的本质是：男频成长长篇必须持续保护主角本人值得羡慕、值得代入、越来越能做什么。

它不意味着所有阶段都由能力发动，也不意味着 production 永远必须从某个叫 Fantasy Seed 的阶段开始。

如果当前架构用 World / Power / Human 分离更好地保护 fantasy，就使用当前架构；未来有更好的结构，也可以替换。

## 3. Agency > Efficiency

好的非对称优势首先扩大“别人做不到，而我能主动介入什么”，而不是把同一工作做得更快、更稳、更精确。

危险信号：

- 探路效率；
- 检测精度；
- 维修成功率；
- 路线优化；
- 资源调度；
- 权限树和 Build 复杂度增加，但主角本人没有更令人向往。

## 4. Fix the Earliest Semantic Collapse

如果某问题在换一本完全不同的新书后仍会出现，找到它第一次被生成成事实的层。

不要把 World 缺失的问题交给 Writer；不要把 Story Program 的同质化交给 Curator；不要让 State 修未来规划。

系统修复 = 下一本新书从零开始也更难掉进同一个坑。

## 5. Few Deep Rules > Many Hard Gates

默认顺序：

1. 删除不必要字段；
2. 移动 authority；
3. 降低上下文可见性；
4. 改 retrieval distribution；
5. 简化/替换生成顺序；
6. 最后才增加 Prompt 约束；
7. 只有前面都不够时才考虑新 Agent / Reviewer / Scorer / Hard Gate。

每新增一层系统，都要证明它的边际收益高于 token、复杂度、失败率与维护成本。

## 6. Supporting Logic Must Not Automatically Become Story Engine

治理、经济、职业、医疗、工程、物流、验证、规则细节可以真实存在。

但“为因果提供支撑”不等于“值得成为读者前景”。

只有当作者真的选择这些为核心阅读体验时，才把它升级成主发动机。

具体优先在：

- 谁想要什么；
- 谁阻止；
- 主角做什么；
- 世界怎么回应；
- 谁得到/失去什么；
- 什么从此改变。

实施步骤只展开到足以支持这些事实。

## 7. Backstage Principles Must Not Become Generated Ontology

Action Space、Net New、Expectation、Mystery Depth、Impact、Compounding 等是作者侧坐标。

它们可以用于评估和约束，但不能被模型直接写成世界内部的资源、组织理念、人生哲学、势力结构或固定字段税。

正确关系：

`后台价值观 -> 当前阶段真正的问题 -> 具体故事事实`

而不是：

`后台价值观 -> 固定 schema -> 为填字段发明剧情`

## 8. Authority Separation Beats Self-Restraint When Leakage Is the Cause

如果 LLM 因为同时看到 A 与 B 而自动把二者合理化成一个主题，优先信息隔离，而不是不断追加“不要合理化”的 negative constraints。

典型例子：

- World 已知 lock -> Character 自动生成 key；
- Power 已知 -> Biography 自动变成能力隐喻；
- Future Plot 已知 -> World 自动预留路线。

独立上下文、deterministic projection、deterministic merge 往往比“请克制自己”更可靠。

## 9. Character Is a Person, Not a Psychological Proof

Human 不是一条人生哲学的证明题。

健康结构倾向于：

- lived facts；
- competing motives；
- stable choice bias under conflict；
- person-specific relationships；
- current desire as mutable state。

允许：

- 贪、怕、赢、爱、性欲、审美、虚荣、享乐、责任、好奇、谨慎、自利、依恋同时存在；
- 这些动机互相冲突；
- 人物知道长期代价却仍做非最优选择；
- 同一种 bias 在不同现场有完全不同的 realization。

禁止把人物净化成“自主、负责、有边界、抗控制”的统一优秀人格。

## 10. Relationship Must Change Choice

“重感情”“关系很深”“团队很信任”不是 Relationship Gravity。

更强证据：

`无此人时会选 A -> 因为这个具体的人实际选 B`

可以改变：

- 风险阈值；
- 去留；
- 路线；
- 时间分配；
- 暴露底牌；
- 机会牺牲；
- 未来力量/生活选择。

换成一个同等有用的人未必成立。

## 11. Growth Is Longitudinal, Not a Stage Tax

全书必须真实变强，但不要求：

- 每个大型阶段升级一次；
- 每个 block 给一个新奖励；
- 每十章开一张新地图；
- 每章证明能力成长。

Power / growth grammar 负责“怎样能变强”；Story 负责“什么时候、通过什么人物和因果真正实现”。

阶段可以主要由 Life、Fantasy 或 World 发动。

## 12. Narrative Compounding > Asset Compounding

真正的复利是故事不回原点：

- 已得能力继续改变行动；
- 旧关系继续影响选择；
- 敌人学会并改变策略；
- 身份变化带来新冲突；
- 旧谜团被重释；
- 过去结果改变未来可能性。

不是资产名词越来越多。

## 13. Concrete Desire > Abstract Importance

“重大”“改变世界”“自由”“成长”“影响力”都很容易是空的。

优先找具体对象：

- 那把剑；
- 那个人；
- 那座城；
- 那场比赛；
- 那个身份；
- 那种力量；
- 那次重逢；
- 那个不能输的公开场面。

如果模型只能解释“为什么重要”，却说不清“人物具体想拿到什么”，优先视为抽象化风险。

## 14. Commercial Quality First, Diversity Second

多样性是为了扩大搜索空间，不是为了完成配额。

四个 candidate 可以有一个明显弱；这比系统把四个都解释成“正确”健康。

不要为了 diversity 强制：

- 一个贪、一个色、一个权、一个恋家；
- 四种阶层平均分布；
- 四种伦理立场平均分布。

但如果四个看似不同却都由同一种心理运动驱动，应判 candidate collapse。

## 15. High Precision / Low Noise for GBrain

GBrain 不追求越多越好。

Source-specific DNA 可以很丰富，但默认 REFERENCE_ONLY。

ACTIVE 的条件：

- 真正新增判断能力；
- 有证据；
- 跨书/跨窗口足够稳定；
- 与已有 craft 不近义；
- 有明确 transfer boundary；
- 不会污染无关 retrieval。

宁可 lane 空着，也不弱卡补位。

## 16. Story Facts Before System Bookkeeping

输出首先要是小说事实：人物、欲望、物、地点、冲突、动作、结果。

系统术语是后台压缩和审计语言。

一旦正文/规划开始大量呈现：

- 权限；
- 节点；
- 路线；
- 资源循环；
- 验证闭环；
- 资产组合；
- 风险管理；
- Action Space / Net New 本身；

先检查系统语言是否泄漏成故事材质。

## 17. Reader-First Prose

Writer 层最常见的 AI 问题不是“句子语法错误”，而是：

- 不重要的物理/流程细节写得太清楚；
- 真正重要的人物目标和规则反而含糊；
- 作者脑中模型清楚，读者脑中模型未建立；
- 动作、内心、旁白、总结重复同一层意义；
- planning language 泄漏正文。

正文先让读者知道：谁在做什么、为什么此刻重要、发生后改变了什么。

## 18. Shock Recontextualization, Not Just Explanation

成熟长篇应保留少量**震撼式长期重释**：旧事实、旧异常、人物行为、宝物或关系在后续被重新理解时，读者不仅“终于知道答案”，还会产生明显惊讶甚至 shock 爽感。

高价值重释同时满足：

- 当下足够意外；
- 回看前文又能找到已存在的证据或异常，而不是临时空降；
- 揭晓后立刻改变力量理解、身份分量、关系结构、敌我判断、宝物价值或世界格局。

来源可以是能力、身份/过去、关系、旧事件、宝物、敌我关系或世界联系；**不默认等于隐藏身世，也不是每阶段伏笔税。**

## 19. Comparative Privilege Needs a Persistent Ruler

**新奇不等于强。** Core Power 应形成读者能比较的优势幅度：同层普通人/天才通常做到什么，主角凭异常提前、低代价或独占了什么原本做不到的特权。允许有条件越级；边界用于防止无条件万能，不应把优势削回普通水平。若候选来自 Novelty Spark，强度也不能靠删除那条单一异常/条件来获得。

世界前台力量尺也不能只在开篇出现一次。境界、等级、潜力、熟练度、亲和度、装备、能量、战绩或排名都可以成为 ruler；不要求全有，也不合成单一总战力分。突破、新能力/装备、公开验证、新强敌、越级结果或世界换挡后，应自然重新校准，让读者持续知道：**主角在哪档、哪里超标、离下一档多远。**

### 19A. High-Value Reveal Needs Reaction + Ruler Calibration

高价值的非对称优势显露不能只靠“人物有反应”，也不能只靠设定解释。默认同时需要两条 reader-facing 通道：

- **Behavioral Repricing**：至少一个关键观察者因为异常证据改变可见动作，例如停手、站起、改口、试探、退距、加价、换装备/战术、保护或重新安排准入；
- **Ruler Calibration**：最有资格的观察者在自身知识边界内，用短而明确的判断告诉读者“正常同层/同类通常能做到什么 → 主角这次具体超出哪里 → 为什么罕见、异常或值得重新判断”。允许有限猜测，但推断不升级为世界真相。

二者应在**首次显露、新层级/质变、新复合用法、进入更高新圈层后的首次重新观察、旧社会估值明显过时**等节点反复出现，而不是第一章讲一次后永久消失。没有懂行者时不凭空加专家，可由最近知情者或已批准的短直接旁白补最小 ruler calibration。

短期爽点可以止于一次行为更新 + 一次专业/世界尺校准，不要求每次都产生长期涟漪；但如果后续仍因这个新估值改变资源、关系、敌意、战术或信息流，就应继续追踪 Social Repricing / Ripple。

## 20. Do Not Overcorrect

修“AI 理性偏见”不等于要求所有人物冲动。

修“工程化”不等于禁止技术题材。

修“治理化”不等于世界没有制度。

修“职业人格”不等于职业不能塑造经验。

修“阶段税”不等于长期成长可以缺失。

每次修复都问：是否把一个默认偏置改成了另一个默认偏置？

## 21. High-Value Orientation ≠ Low-Value Explanation

“少解释”不是目标，**更高的信息价值密度**才是目标。

审计 exposition 时先分两类：

- **Low-value explanation**：一个结果已经成立后继续换证据证明；重大选择已经清楚后继续论证人物为什么会这样选；决定完成后的停车、搬运、登记、排布、检测等普通实施被完整展开。它们通常应被 Result Stop / State Advance 压缩。
- **High-value Reader Orientation**：重要势力、地点、身份、资源、力量层、社会位置或生活方式第一次真正改变人物选择时，读者需要知道“它是什么、为什么此刻有分量、普通人或当前 POV 通常知道什么”。这类信息可以用短直接旁白高效释放，本身可以建立欲望、风险、世界尺度与期待。

正确 authority 链是：

`World 提供已批准事实 → Outline 决定首次释放时机 → Curator 只投当前相关安全事实 → Writer 直接、短促地表达 → 回到动作`

如果 World 根本没有移动现实、社会常识或价值坐标，不允许 Writer 临时补制度；如果 World 有但正文没讲，检查 Outline / projection / Curator，而不是继续要求 Writer “show more”。反过来，也不要为了 Reader Orientation 建百科、每章 exposition 配额或新 Reviewer。

## 22. Reader Knowledge = Authority × Timing × Delivery × Realization

“World Vision 里写过”不等于读者知道。世界信息进入正文要分四层判断：

- **Authority**：事实已批准，且属于章节期可安全使用的公共事实；
- **Timing**：第一次真正影响当前事件时才释放，Future Plan 仍安排为 reveal 的答案不能提前；
- **Delivery**：runtime 是否把当章需要的事实实际投给 Curator / Writer；
- **Realization**：正文是否最短充分说清“是什么 / 为什么重要”，然后回到动作。

开篇生活 Orientation 与战力 Ruler 分工：只说“普通人没境界 / 打不过二阶”仍可能让读者不知道自己生活在怎样的世界。named 势力首次重要登场时，若世界已有安全公开类别，应直接让读者知道一次“它是什么类型的存在”，而不是靠外观猜；动机和长期谜底继续未知。

高价值解释应**替换**低价值重复验证或实施，而不是叠加在上面。

## 23. Established Supporting Skill Should Collapse to Story Result

手艺、诊断、维修、制作、路线、车具、医学、调查等 Supporting Skill 可以让人物真实，但一旦其方法已在前文成立、且它不是当前 Core Fantasy：

> **后续复用默认写它让人物完成了什么，而不是重新写他怎样一步步做到。**

只有本章出现新边界、失败、反制、质变，或该专业本身就是作者选择的第二幻想轴时，方法才值得重新展开。

审计实施化时先追 Director / Curator：如果上游把“利用某专业判断 → 调整 A → 处理 B → 固定 C”作为事件合同或 `Relevant Plan`，Writer 的扩写往往只是忠实 realization。不要在这种情况下只给 Writer 加“少写点”。

## 24. Access / Reward Must Not Pay a Qualification-Process Tax

当 Outline 已经明确某个邀请、入场资格、名额、工作机会、身份待遇、奖励或高层人物认可已经真实存在时，下游不能为了“让主角显得配得上”自动补一轮试工、检查、考核、观察、登记或再次验证。

先问：**这段资格流程是 Plan 真正选择的故事事件，还是 LLM 为合理化收益自动征收的流程税？**

若 Plan 没安排，默认直接进入：

`机会已经成立 → 主角接受 / 拒绝 / 延后 → 选择带来的后果`

这不等于所有资格剧情都不该写；作者真正选择考试、竞赛、选拔、入门考核作为故事发动机时当然可以展开。审计针对的是**奖励已经成立后又被自动要求二次证明**。

## 25. Do Not Invent Competence Filler to Make the Protagonist Look Useful

低动作章节常见一个模型偏置：本章真正价值是 World Entry、势力首次登场、关系立场、误判、世界信息或局势换挡，但模型担心“主角没做事”，于是临时发明排车、修车、诊断、路线、搬运、清点、受力、制作等小问题，让主角表现专业能干。

这会把 Supporting Logic 再次推到前台。

审计时问：

- Outline 是否真的安排了一个值得展开的技术问题？
- 这个技术动作是否改变核心冲突、胜负或不可逆结果？
- 若删掉操作过程，人物立场、世界信息和局势变化是否仍完整？

如果答案说明技术问题只是为了“让主角显得有用”，应删除 Competence Filler。**观察、站队、拒绝、跟随、守住位置、提出一句判断或作出选择，本身就可以是完整而有力的主角行动。**

## 26. Unresolved Long-History Facts Must Remain Unresolved

正文需要完整感，不等于 Writer 获得补写旧历史的 authority。

如果 Canon、Curated Context、Open Promise 或章节上下文已把某段过去标为未知、未解释、真假未定、原因未明：

- 除非 Director Contract 明确批准本章新增哪一个确定事实，否则只能写当前动作、即时证据、对白措辞、感官和人物暂时判断；
- 不得补造几十/几百章前的秘密经历、旧对话、隐藏动机、既有知识或世界机制；
- 不得因为 Reader Orientation 需要公共背景，就顺便回答未来 reveal；
- State Extraction 也只能记录正文真正确定的新事实。

正确边界是：

> **已批准的公共事实可以直接说明；未批准的历史答案必须继续未知。**

审计时若正文出现 retrospective canon，先查 Director / Curator 是否错误投放了答案；若上游仍保持 unknown，而 Writer 自行补全，才判 prose authority 越界。

## 27. Deep Craft Research, Narrow Runtime

场景研究可以不断加深，但章节模型看到的信息不应同比增长。

稳定结构是：

`source evidence → fidelity audit → cross-book craft → Curator short projection / NONE → Primary`

以及：

`validated local failure → short Revision Watch → Preservation-First Reviser`。

完整原著 evidence、书名、locator、完整 Generation/Revision Lens 不进入 Writer。新 Scene Primary 只有在主要阅读问题、持续状态、beat engine、Stop/Handoff 都实质不同，且 compact conditional 的 A/B 不足时才成立；“这种场景重要”或“研究很多”不是 taxonomy 权限。
