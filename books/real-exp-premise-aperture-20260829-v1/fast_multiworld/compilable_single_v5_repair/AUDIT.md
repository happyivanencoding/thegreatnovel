# SELECTED PREMISE REPAIR V5 AUDIT

## Verdict

- **Repair path: FAIL.**
- **Protected core validation: FAIL before compiler recheck.**
- **Downstream: NOT AUTHORIZED.**
- **Production default: unchanged.**

## Protocol

The source was the preregistered V4 S2 `一城吞门`. One Luna-high call was allowed to repair only the four independent-compiler conflicts. Code locked the candidate title plus four protected fields:

- `一句话货架简介`;
- `Protagonist Ontology-only Direction`;
- `主角反复会做的新动作`;
- `不可磨平的三点`.

Only a repaired card that preserved all four fields and then received strict compiler `PASS` could enter downstream.

## Result

The repair substantially rewrote the causal machinery and did close several known bridges, including:

- requiring the entire shed to physically pass the one real threshold;
- keeping the same real door rather than inventing a rear-wall door;
- explicitly establishing five witnesses;
- defining a stepwise public shell scale instead of treating one core as automatic rank 9.

However, it omitted the entire protected `### 主角反复会做的新动作` field. The deterministic validator therefore stopped before any compiler recheck. It was not legal to copy the old field back after seeing the result, because that would turn code into a post-hoc repairer and hide model noncompliance.

## Architecture Consequence

This single test does not prove selected-premise repair is impossible. It proves that an automatic repair loop is not currently reliable enough to freeze:

- the repair call expanded into a much longer redesign instead of a narrow causal patch;
- explicit prompt-level protection did not guarantee field preservation;
- code-locking correctly prevented the changed card from proceeding;
- no new creative candidate was substituted and no downstream calls were spent.

Current recommendation: keep `Selected Premise Contract Repairer` and its validators `RESEARCH_ONLY`. After Compiler failure, the production candidate flow should still return the exact conflicts to the author rather than silently auto-repairing.
