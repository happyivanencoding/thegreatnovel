# Cross-Window Findings

1. 成功线必须先被压缩成读者可追踪的“判定物＋阈值＋出局动作”，过程才有张力。材料次数、分数线、前五十、前三、药单、出口、成品与丹雷均如此。证据：TD-01、TD-02、TD-03、TD-06、TD-10、TD-11、TD-13。

2. 应展开的不是“考试过程”本身，而是会改变判定的铰链：有限次数、规则异常、队伍失配、最后名额、成品能否被保住。无新差异的重复操作、普通赶路和多数人的同类失败应压缩。证据：TD-03、TD-04、TD-05、TD-07、TD-08、TD-13。

3. 旧价格必须落在资格之外的现实行动空间：失去参赛资格、无法进入内院、家族被除名、失去修炼资源、错失终局石台。只有“赢一场”而无后续权利变化时，比赛很难承载长篇强度。证据：TD-02、TD-06、TD-07、TD-10、TD-11、TD-12。

4. 失败后果要立即改写下一步，而非只给情绪：退场、材料耗尽、失去资格、被迫保命退出、不能进入终局；反之，成功应立即生成新入口或资源。证据：TD-01、TD-03、TD-05、TD-08、TD-11、TD-13。

5. 他人反应的作用不是添掌声，而是公开重定价：评审改变态度、竞争者改写预判、裁判调整名额、组织将结果变成资源与身份。证据：TD-01、TD-02、TD-05、TD-08、TD-10、TD-13。

6. “规则看似简单、实际有隐藏铰链”只能在现场已给出可复核异象时使用；反例是高阶资格认证，过程没有新的选择或读者需理解的规则时，结果可直接压缩。证据：TD-04、TD-09，以及TD-03。

# Counterexamples & Boundaries

- TD-09 证明：资格认证不必展示完整试题。若其唯一作用是给后续事件提供合法身份，且室内过程不改变关系、资源或判断，门外等待与结果即可。
- TD-04 证明：并非所有规则都必须在开考前完全透明。规则异常可成立，但必须先让“照规则做仍失败”的证据出现，并让主角支付一次识别成本。
- TD-06 证明：多人围攻不天然等于裁判失职。该窗的混战规则未禁联手；若场景承诺单挑或固定对阵，此做法不能迁移。
- TD-07 证明：试炼可以从“过关”转成“资源竞争”，但前提是规则明确允许对抗、资源可转移、资源会持续影响后续生活。
- TD-13 证明：终局可在看似胜负已定后继续，但只有未完成的正式验收仍可能撤销结果时；不得为拖延高潮而另加一层验证。

# What Existing Skill Misses

现有 `trial_challenge` 已覆盖规则、成功线、失败后果、差距、真实反馈、压缩重复与通过后停止。新增而非近义重复的判断能力应是：

1. “旧价格”不是泛泛失败后果，而是资格转化前后具体失去／获得的行动空间。应先明确门票能换来什么，再决定试炼是否值得展开。

2. “资格验证”与“判定铰链”应分流。前者可像 TD-09 一样黑箱压缩；后者如 TD-04、TD-08、TD-13，必须展开到读者能复核结果改写的那个节点。

3. 多阶段试炼的阶段切换要结算权利，而非只换地点：第一层通过后获得什么、第二层保命退出会失去什么、何时正式取得终局资格，需要在切场时说清。

4. 对“隐藏规则”的适用边界：必须有失败样本或现场反馈作为证据，不能让作者在答案揭晓时单方面改题。

5. 团队型试炼中，关键应是规则怎样迫使队伍形成、失配或重组；不是平均分配每名队员的战斗展示。

# Candidate Transfer Rules

1. 资格线先落到可见物

   - Applicability：外部机构、榜单、比赛或试炼将产生身份、入口、资源、职位等实质变化。
   - Rule：在主角做关键动作前，给出判定物、阈值、失败后的下一步和通过后的新权利。
   - Stop rule：判定物被确认、新权利已经成立后，转入其实际使用，不再复述“他通过了”。
   - Failure pattern：只说“这很重要”而未说清资格到底换来什么，后续胜利只能变成空泛热闹。

2. 只展开会改写判定的铰链

   - Applicability：试炼包含重复操作、大量参赛者或长时间移动。
   - Rule：保留有限次数、规则异常、关键对手、队伍失配、最后名额、结果复核等能改变成功概率的拍点；同类过程用结果压缩。
   - Stop rule：铰链已被动作和反馈证实后，不再逐轮证明主角“仍然厉害”。
   - Failure pattern：每次操作都给完整描写，读者已知结果却被迫等待同类动作结束。

3. 隐藏铰链须先由现场支付验证成本

   - Applicability：表层规则与实际成功方法存在差异。
   - Rule：先给至少一个失败样本或真实异常；主角可付出一次材料、时间、位置或机会成本来验证，再依据结果修正。
   - Stop rule：异常原因可由现场细节复核后，立即转入执行与结果。
   - Failure pattern：末段临时宣布“真正规则”，此前没有可观察异常，导致规则像作者补丁。

4. 多阶段试炼每过一层都结算一次权利

   - Applicability：入口关、探索关、终局关彼此相连。
   - Rule：每层结束必须说明保留了什么资格、获得什么任务物、退出会失去什么；下一层只承接已经成立的状态。
   - Stop rule：下一层的目标、退出代价与成功线清楚后，不重讲上一层。
   - Failure pattern：只写换地图，不写资格状态，读者无法判断保命、绕路或放弃是否合理。

5. 团队试炼用“规则压力”筛选协作，而非排队展示成员

   - Applicability：规则允许联手、资源争夺、信息不对称或多人同时承压。
   - Rule：让一个具体规则压力迫使队伍决定指挥、信息、分配或撤退；只展开会改变整体结果的成员动作。
   - Stop rule：团队组织已证明能改变胜负后，切回最终对局或资源结算。
   - Failure pattern：每名成员轮流炫技，却没有任何行为改变队伍能否过线。
