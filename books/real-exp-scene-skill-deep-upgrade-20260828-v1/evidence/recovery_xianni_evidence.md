# Cross-Window Findings

1. 恢复的完成标尺应是“旧缺损禁止的行动重新可做”，或“旁人据此改写选择”，不是一句状态结论。肉身重成后可安全祭宝（05）；石化醒转后能改变路线救人（07）；部分伤愈后可返宗（11）；宋致恢复自我后可归家（12）；婉儿醒后可共同生活（13）。
   Evidence IDs：01, 05, 07, 09, 11, 12, 13。

2. 疗程只在方法、代价或恢复阈值改变时展开；稳定重复的运功、时间和移动应压缩。雷域十年与甲子岁月只保留身体生成节点（05）；七夕术只展开第三至第五日的失败阈值（06）；三日、半月的疗伤只保留七八成与八九成两个行动阈值（11）；长期分离处理只保留其伦理理由与归家结果（12）。
   Evidence IDs：05, 06, 11, 12。

3. “部分恢复”不是弱结尾：只要人物明确还缺什么、为什么已足以行动、行动会去哪里，恢复就能驱动下一章。司徒南尚缺肉身但已取得路径（02）；心神只恢复一瞬也足以重新接管危机（03）；王林带伤可继续夺取生机（04）；七八成伤愈即可返宗（11）。
   Evidence IDs：02, 03, 04, 11。

4. 当恢复来源对外可见且可争夺，场景的主引擎立即由“疗伤”改为“资源占有 / 战斗”。生机吸收使敌人先误判后恐惧（04）；凶兽生机被旁人识别后，疗伤转为公开抢夺（08）；西子凤的修复使施害者受清算、身份关系重排（09）。
   Evidence IDs：04, 08, 09。

5. 关系性恢复不可只验证被恢复者的情绪；还应验证他者的身份、安全或共同生活是否被重新允许。李慕婉只获得可保存的一丝生机而未被伪装成复活（06）；李倩梅的付出使苏醒者承担新的行动责任（07）；宋致在残魂分离后仍保有自我与家（12）；婉儿苏醒后能共同选择未来（13）。
   Evidence IDs：06, 07, 12, 13。

# Counterexamples & Boundaries

- 第827章《姚冰云》51855–51869：王林只说“先找地方疗伤”，随即被姚冰云持续追踪；没有发生可验证恢复。它只能证明“受伤后的行动意图”，不纳入恢复 scene evidence。
- 第995章《魂》61711–61719：众人推测青霖重伤未愈并因此觊觎仙府；这是把“未恢复”当成入侵机会的情报前提，不是恢复场景。
- 第1194章《破罗》73532–73544：王林带伤强行破罗盘，核心问题是逃脱与危机处置，不是恢复；不得因出现“寻找疗伤之地”而误分类。
- 第1428章《疯狂的念头！》87174–87231：长期闭关疗伤的强敌被王林视作突袭窗口。它是反证：当读者主要追问“能否乘其未愈击杀”，Primary 应是 `combat` / `stealth_infiltration`，不是 `recovery_restoration`。
- 第1489章后段 90949–91051：西子凤后续直接提升修为，属于 `breakthrough_advancement`；不可把恢复伤势、恢复容貌、传功突破混为一个没有边界的“恢复”。

# What Existing Skill Misses

当前 [`recovery_restoration`](C:\dev\tgn-story-mvp\.agents\skills\novel-scene-skills\scenes\recovery_restoration.md) 已覆盖“缺损具体化、可观察功能、压缩重复疗程、恢复后转场”。本组证据带来的新增判断能力是：

1. “功能恢复”需区分三条阈值：能脱离危险、能承担下一项决定性动作、可把旧缺损视为暂时不重要。现有 Skill 要求写清能/不能做什么，但没有要求按下一项任务选择恢复阈值；第1851章证明七八成就可转移，第718章则必须重获肉身才可祭宝。

2. 当恢复资源被他人看见并可竞争时，主场景必须切换。现有 Skill 未明确要求判断“疗伤来源是否已变成公开资源”；第602、1442章中，若继续把它写成静态疗伤，就会漏掉真正发生的抢夺、威慑与敌友重排。

3. 关系性恢复需审查“恢复是否抹掉第三方的自我”。现有 Skill 说关系核心变化交由 `relationship`，但第2042章新增的是具体伦理与场景判断：快取会杀死承载者时，慢处理及其生活结果本身就是恢复的验证。

4. 长线复苏应以“共同生活权限”收束。现有 Skill 有“重新进入关系”，但第2087章提供更窄的可执行判断：不要在苏醒后继续解释疗法；给双方一件此前不可能共同完成的生活行动即可。

# Candidate Transfer Rules

1. **行动阈值先行规则**

   - Applicability：人物未完全恢复，但下一项任务有明确风险、时限或安全条件。
   - Rule：写清“尚存缺损 + 当前已恢复到何种可用功能 + 因此立刻去做什么”。
   - Stop rule：下一任务已启动，或恢复不再改变人物可承担的行动。
   - Failure pattern：只写“七成恢复、八成恢复”而没有任务与能力差异，形成状态栏报告。
   - Evidence IDs：02, 03, 11。

2. **恢复资源转场规则**

   - Applicability：疗伤来源可被现场他人感知、抢夺、限制或定价。
   - Rule：在首次可见收益后，立即写出至少一种外部反应：争抢、封锁、合作要价、恐惧撤离或报复。
   - Stop rule：资源归属及其带来的冲突已成立，转入 `resource_economy`、`combat` 或 `chase_escape`。
   - Failure pattern：主角持续吸收资源，周围角色像不存在，导致恢复脱离场景关系。
   - Evidence IDs：04, 08, 09。

3. **结构节点压缩规则**

   - Applicability：疗程跨越多日、数年或重复操作，但中间没有方法、代价、关系或风险的新增变化。
   - Rule：只展开“第一次有效反馈、关键失败/代价、功能重现、首次使用”四类节点；其余用可信时间跳切承接。
   - Stop rule：恢复状态已被首次真实行动验证。
   - Failure pattern：把每次服药、运功、守候都写成段落，时间很长但状态不变。
   - Evidence IDs：05, 06, 11, 12。

4. **承载者保全规则**

   - Applicability：恢复某人会侵占、分离、改写或伤及另一人的身体、记忆、身份或生机。
   - Rule：先让人物在“速度 / 完成度 / 他者存活”间作出明确选择；结果必须验证承载者仍保有什么，而非只报告目标恢复。
   - Stop rule：目标状态与承载者后续生活均已可观察。
   - Failure pattern：把无辜承载者当一次性治疗材料，主角恢复了，关系代价却被叙事抹掉。
   - Evidence IDs：06, 12。

5. **复苏后的共同动作规则**

   - Applicability：长期失去、沉睡、失忆或关系断裂终于解除，且主冲突已让出体验空间。
   - Rule：用一个低强度、具体、共同选择的行动验证关系恢复，而非用旁白宣布“终于圆满”。
   - Stop rule：双方新的相处权限已通过行动成立。
   - Failure pattern：苏醒后立刻塞入新的灾难，或反复确认“真的醒了”，吃掉已兑现的情感 payoff。
   - Evidence IDs：07, 13。
