# 《炉藏万象》可选序章 → 人物型第一章隔离实验

实验标识：`real-exp-prologue-character-opening-v1`

日期：2026-08-22

工作分支：`principal_dev_new_sys`

## 目的

验证把“世界尺度 / 当前秩序 / 黑炉镇倒计时”放入一个可选序章，再把第一章收束到沈燧的具体困境、行动、断镐残响和真实逃生结果，是否能降低当前 Hybrid Chapter 1 的首次阅读认知负担。

本实验不重新设计《炉藏万象》，只重排表达和开篇信息结构。核心假设是：原世界模型可以保留，但不必和主角、空间、能力、矿难行动同时在第一章完成。

## 冻结边界

- 使用同一套 Fantasy Seed、World Vision、Story Program、BOOK 设计、Outline / Future 10、核心人物、核心能力和第一章现实结果。
- 不改变沈燧、黑炉镇、封炉、塌方、断镐、第一次借用未完成力量打开生路、后续裂路器 / 炉窟方向。
- `PROLOGUE.md` 是独立实验 artifact，不伪装成 `chapter-0000.md`。
- 不修改 Chapter numbering、State Delta、Canon schema、Run Ledger、Workflow State、前端章节编号逻辑、生产 Prompt 或生产默认架构。
- 不生成 Chapter 2—10，不运行 Reviewer，不自动重写，不给正文做文学评分。
- 不把本实验正文写入现有 `candidate-b` 的 `BOOK.md`、`chapters/` 或 Canon。

## 结构控制

序章只完成：炉火 / 灵脉的生存后果、玄烬仙宗的决定性力量、封炉对普通矿镇的意义、黑炉镇三日倒计时；结尾停在“三天后封炉”。序章不兑现核心能力，也不解释后续完整体系。

Chapter 1 假定读者已经读过序章，按“人 → 问题 → 后果 → 行动 → 异常 → 能力最简单的当前理解 → 利用 → 结果”推进。它必须保留早兑现：断镐残响真实打开生路，矿工 / 伤者实际撤出，沈燧留下黑铁锋片并被重新看待，裴照川的异常回收命令和废弃炼器窟作为短落点与下一章推动。

正文表达临时优先级：清楚 > 顺畅 > 有画面 > 文学感。详细写正常办法为什么不行、沈燧的决定、断镐操作和风险、真实结果及人物反馈；压缩重复搬运和无新信息的工程过程。

## 实际调用协议

本轮只计划 4 次顺序执行的真实 `luna_worker` 内容调用：

1. 序章正文；
2. Chapter 1 Director；
3. Chapter 1 Curator；
4. Chapter 1 Primary 正文。

每次调用前保存完整 prompt，调用后立即保存原始 response。后一个调用只能读取前一个调用已经冻结的 artifact。调用失败或内容不理想都属于实验结果；本实验不因文学偏好追加重试。

## 验收边界

实验只回答结构问题，不作总体文学判断：

1. 序章是否把宏观认知收束到黑炉镇三日倒计时，并在能力兑现前停止；
2. 新 Chapter 1 是否更快进入具体人物问题，且没有重新讲完整宏观世界；
3. 第一次能力是否仍在 Chapter 1 内造成不可替代的现实结果；
4. 能力操作是否达到“操作清楚、原理神秘”的最低理解层级；
5. 结果后的短暂落点是否交代活下来的人、人物反馈、沈燧确认的能力和下一章入口；
6. 是否出现明显退化或事实越界。

这不是生产批准，也不构成 Opening Contract 的修改建议；结论只对本次隔离文本实验负责。
