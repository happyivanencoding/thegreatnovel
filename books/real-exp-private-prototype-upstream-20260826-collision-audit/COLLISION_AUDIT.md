我会把这当作一次“合同语义是否改变了编译结果”的只读审计：先核对已有边界，再只用你给出的 B0/B1/A0/A1 与 Human 片段做文本证据判断，不重写方案、不加新门禁。## 总结判断

这次实验基本成立：问题不是某个 Power 不够强，也不是 World 不够复杂，而是旧 `Story Program legacy contract` 把阶段默认编译成了“能力参与—能力成长—关键获得—净新增”的 Fantasy Engine 单位。

`native Collision compiler` 确实把阶段发动权重新分给了 Life / World / Fantasy 的真实碰撞。Human schema 的替换也与这个方向一致，但要避免把 competing motives 再次编译成新的字段清单。

### 1. Legacy contract 是可复现的最早语义坍缩点

是，但“最早”应理解为目前可观察到的最早语义坍缩点，不是已经用底层 trace 证明的唯一代码根因。

证据有三层：

- B0 → B1 基本保持 World、Power、Human、Story GBrain、Sol high，只更换合同；输出从 1143 行、重复两遍，变成 188 行、唯一版本。
- A-old-blind → A1 保持 blind-selected 离印及其他输入，只更换合同；旧合同超过 15 分钟无产物，native contract 在 485 秒完成唯一版本。
- 这不是同一 Power 的偶发情况：分流真元和离印两个完全不同的能力，都在旧合同下被压成阶段化能力税。

旧合同自身已经暴露出坍缩结构：每阶段都要求“核心优势怎样参与”“主角一级成长”“关键获得”“阶段净新增”。即使上游写了“世界不会被能力解释”，编译器仍会要求每个阶段交出一份能力成长证明。

所以双输出和超时是运行层症状；真正的语义根因是旧合同强迫阶段围绕 Fantasy Engine 完成。

### 2. B0 → B1 确实让 Life / World Engine 获得阶段发动权

最直接的证据是 B1 有两个阶段在没有新能力、掉宝或突破的情况下仍然完整成立。

阶段3“万灯不等人”明确写着：

> “陆回川没有获得新能力，也永久失去了本届剑池资格。”

它的发动机是阮棠、失踪船、错误灯痕与陆回川的偏爱。核心能力只帮助他撑船舱、战水妖，却不能替他判断该相信哪条线索。阶段结果是救人、误判死亡、关系确认与失去剑池资格。

阶段5“寒关两边”更明确：

> “本阶段没有新的标志性能力成长。”

以及：

> “带着伤亡和污名离开，没有掉宝，也没有突破。”

这一阶段由迁徙、粮仓、军令、矿镇伤亡和人妖两边的现实利益发动。陆回川放弃军功，失去结丹灵物，承担三名矿镇修士死亡的后果。它仍然有男频冲突强度，但没有被改写成下一次升级。

B0 则更容易把关系和世界冲突接回成长收益。例如万灯河阶段虽然核心是阮棠和追踪，但仍安排：

- “主角一级成长”
- “关键获得”潮序铜牌
- “阶段净新增”黑日岛入场资格

赤脉山阶段的矿权、石晚棠和宗门冲突，也被同步编译成元婴/化神成长、火髓、本命飞剑和远距协同。那些内容本身并非错误，问题在于它们被结构上变成每阶段必须交付的结果。

B1 的关键变化是：成长仍可出现，但不再拥有阶段所有权。

### 3. A0 / A-old-blind → A1 也改善了

改善成立，而且白盐海和无面案提供了很强的证据。

A1 的阶段3“白盐海不开同一条路”明确规定：

> “Core Fantasy主要服务海雾、盐沟和两线战场，不在此阶段强行产生新形态。”

结果也确实没有给沈照野期待中的完整海甲，反而是：

- 旧港被毁；
- 数千人失去生计；
- 韩戍成为敌人；
- 段停山关系破裂；
- 一条离体臂甲被毁；
- 没有获得预期材料。

这说明白盐海首先是世界冲突，不是下一件相材的领取点。

阶段4“无面者知道身体怎么死”也没有把案件强行解释成新能力来源。它的核心是祝青棠、授业者、闻砚生和沈照野对身体边界的选择。最终主角：

- 放弃可据为己有的相合器官；
- 先救受害者；
- 左眼感官结构被永久毁掉；
- 案件仍留下两具不属于闻砚生的尸体。

这里的核心幻想服务追凶和受伤，不负责发放成长奖励。

青铜王庭阶段仍然有七十级、旧体相谱和完整兽材，但这不构成回退。因为阶段的主发动机是使者遗体、王庭继承、边城与祝青棠的选择；材料是世界冲突中的真实结果，不是“本阶段必须获得一件新相材”的模板义务。

因此，native compiler 并没有删除 Fantasy，而是删除了 Fantasy 对每个阶段的垄断。

### 4. Native contract 仍然保留男频成长和 Core Fantasy

没有从一个极端走到“人物文、成长消失”。

B1 的 progression spine 很清楚：

- 潮前十日：普通人进入修炼，第一次分流；
- 九檐留名：从偶发异象到可训练的攻守并行；
- 赤脉有主：自由调配主次，形成长期本命法宝；
- 黑日归航：高阶功法、飞舟与异位协同；
- 黑骨城开：渡劫级战斗，最后主动合流。

而且能力持续兑现，不只是设定宣言：

- 船上同时护舟与救人；
- 试剑中攻守同发；
- 赤脉山以不同真元节奏完成决胜；
- 黑日岛同时驾舟、御剑、救援；
- 黑骨城让飞剑、飞舟、退路和战场落点同时推进，最后合为一击。

A1 也保留了完整的百铸身升级脊柱：

- 断肢仍动；
- 多向作战；
- 分离感知；
- 蜕壳与局部战斗体；
- 九十至一百级的万铸身。

区别只是阶段不再机械地“拿材料—升级—展示”。例如白盐海阶段的损失和无面案阶段的感官毁坏，本身就是成长脊柱的一部分：主角获得新行动空间，也承担身体结构永久消失的代价。

所以 native contract 保住了：

- 明确的境界/身体成长；
- 可复述的能力进化；
- 连续的资产与战斗复用；
- 核心幻想的视觉兑现；
- 男频读者需要的占有、展示、反制与升格。

### 5. World 不需要继续加“正交删除测试”等生产规则

不需要动 World。

现有 protagonist-blind World 已经基本达到目的。B1 和 A1 都证明世界在主角之外运行：

- 黑日岛各方本来就在争夺；
- 白盐海兽群本来就在迁徙；
- 无面剖师本来就在杀人取器官；
- 青铜王庭本来就在争夺继承与独立；
- 母骨炉和睡脊本来就是世界级冲突；
- 这些事件都没有因为主角的能力才诞生。

A1 甚至明确写出：

> “这不是黑日岛的后续机关，也不是分流真元引发的世界反应。”

真正需要修复的是 Collision compiler 如何从这些独立运行的世界事件中选择阶段主冲突，而不是继续给 World 添加删除测试、独立性规则或额外验证层。

“正交删除测试”最多只能作为一次性研究审计手段，不应进入 production contract，也不应新增 Agent、Reviewer、scorer 或 Hard Gate。

### 6. 新 Human schema 与 native Collision 是同方向的

是同方向，而且输出已经显示出配合效果。

旧 Human 把人物压缩为单一 Core Obsession：

> “他想追逐有质地的生活。”

随后多数行为都被解释成这个 obsession 的证明。这容易让人物变成一个稳定主题的演示器。

新版则提供：

- 生活事实；
- 多个互相竞争的动机；
- Stable Choice Bias；
- 具体关系原点；
- 不同代价下可能作出的不同选择。

这与 native Collision 的要求完全一致。B1 中陆回川会：

- 为阮棠放弃剑池；
- 选择错误灯路并造成死亡；
- 放弃军功和结丹灵物；
- 不接受“以后补偿”的模糊安排。

A1 中沈照野会：

- 为短暂集市拒绝长期供养；
- 为救队员放弃最昂贵甲材；
- 先参与屠兽，再因现场改变立场；
- 把退相钉用在祝青棠身上；
- 在母骨炉阶段明确把成长机会留给自己。

这些不是单一执念的重复证明，而是竞争动机在具体现场中的选择。

唯一需要保留的边界是：新版 Human 的多个动机不能再次被编译成“每阶段各兑现一个动机”的新表单。它们必须作为可互相冲突的驱动力，由当前碰撞选出主导项；其余动机可以被压抑、损失或延后。

### 7. 最多两处 production 根改

只建议两处：

1. **替换 Human schema**

   移除“Biography 逐条证明单一 Core Obsession”的旧结构，改为：

   `生活事实 + competing motives + Stable Choice Bias + person-specific relationships`

   这会让人物在不同阶段真正拥有可能改变路线的私人动机。不要增加 Human scorer、人格 Agent 或长期状态系统。

2. **替换 Story Program legacy contract / compiler**

   直接移除旧阶段表单，使用 native Collision contract：

   - 每阶段先确定真实碰撞主体；
   - Life / World / Fantasy 可以轮流发动；
   - 能力参与、升级、获得、净新增全部改为条件项；
   - 阶段必须留下行动空间、关系/身份、敌人策略或世界事实的不可逆变化；
   - Core Fantasy 保持持续可见，但不再拥有每阶段的编译权。

World、Power、Outline 不要因此继续加规则、加字段或加测试。它们现在已经提供了足够的独立事实、能力边界和长期成长材料；需要改的是 Human 的人物输入形状，以及 Story Program 对这些输入的编译方式。
